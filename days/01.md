# Terraform Day 1: Create Your First AWS S3 Bucket

The Cloud Engineering team has requested the creation of an Amazon S3 bucket using Terraform to begin **Infrastructure as Code (IaC)** adoption. Follow this hands-on guide to provision, verify, and clean up an S3 bucket using Terraform.

---

## Learning Objectives

By the end of this exercise, you will:

- Install Terraform on your local machine
- Configure AWS credentials
- Create an S3 bucket using Terraform
- Enable bucket versioning
- Apply the configuration and verify the bucket exists
- Destroy the infrastructure cleanly when finished

### Step 0c: Configure AWS Credentials

```bash
aws configure
# AWS Access Key ID:     AKIAxxxxxxxxxxxx
# AWS Secret Access Key: ****************************************
# Default region name:   ap-south-1
# Default output format: json
```

This creates two files:

- `~/.aws/credentials` — your access keys
- `~/.aws/config` — region + output format

> 💡 **Tip:** Never commit AWS credentials. Use environment variables, `~/.aws/credentials`, or tools like `aws-vault` / `direnv`. For multi-account setups, use **named profiles**:
>
> ```bash
> aws configure --profile dev
> AWS_PROFILE=dev terraform apply
> ```

## Part 1: Provision the S3 Bucket

### 1. Create a Terraform project directory

```bash
mkdir terraform-day1
cd terraform-day1
```

### 2. Create a Terraform configuration file

```bash
touch main.tf
```

### 3. Add the following configuration

```hcl
terraform {
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 6.0"
    }
  }
}

provider "aws" {
  region = "ap-south-1"
}

resource "aws_s3_bucket" "demo" {
  bucket = "your-unique-bucket-name"
}

resource "aws_s3_bucket_versioning" "demo" {
  bucket = aws_s3_bucket.demo.id

  versioning_configuration {
    status = "Enabled"
  }
}
```

> ⚠️ Bucket names must be **globally unique** across all of AWS. Replace `your-unique-bucket-name` with something like `yourname-terraform-day1-2026`.

### 4. Initialize Terraform

Downloads providers and sets up the working directory.

```bash
terraform init
```

Expected output ends with:

```
Terraform has been successfully initialized!
```

### 5. Validate the configuration

Catches syntax errors and internal consistency issues.

```bash
terraform validate
```

### 6. Preview infrastructure changes

Shows what Terraform *will* do without making changes.

```bash
terraform plan
```

### 7. Create the S3 bucket

```bash
terraform apply
```

Type `yes` when prompted:

```
Do you want to perform these actions?
  Terraform will perform the actions described above.
  Only 'yes' will be accepted to approve.

  Enter a value: yes
```

### 8. Verify bucket creation

```bash
aws s3 ls
```

Or query the API:

```bash
aws s3api list-buckets --query "Buckets[].Name"
```

You should see your new bucket in the output.

## Part 2: Cleanup — Destroy Infrastructure

### 9. Preview resources to be destroyed

```bash
terraform plan -destroy
```

Always review this output carefully before confirming.

### 10. Destroy the S3 bucket

```bash
terraform destroy
```

Type `yes` when prompted.

### 11. Verify bucket deletion

```bash
aws s3 ls
```

The bucket should no longer appear in the list.

### 12. Remove local Terraform files (Optional)

```bash
rm -rf .terraform
rm -f terraform.tfstate
rm -f terraform.tfstate.backup
rm -f .terraform.lock.hcl
```

## Part 3: Targeted Operations

### Destroy a single resource

You don't have to destroy *everything*. Target a specific resource with `-target`:

```bash
# Destroy only the bucket (not the versioning resource)
terraform destroy -target=aws_s3_bucket.example
```

You can also use the resource address from your config (e.g. `aws_s3_bucket.demo`).

Other useful targeted commands:

```bash
# Apply a single resource
terraform apply -target=aws_s3_bucket_versioning.demo

# Plan a single resource
terraform plan -target=aws_s3_bucket.demo
```

> ⚠️ Use `-target` sparingly. It's great for surgery, but for normal workflows, let Terraform manage the full graph.

## Good to Know

### What is Terraform?

| Concept | Description |
|---------|-------------|
| **Infrastructure as Code (IaC)** | Define infrastructure using code instead of clicks |
| **Declarative Language** | You describe the *desired state*; Terraform figures out *how* to get there |
| **Provider-Based Architecture** | Works with AWS, Azure, GCP, Kubernetes, and 3,000+ others |
| **Automation Friendly** | Easily integrated into CI/CD pipelines |
| **State Management** | Tracks what it manages so it knows what to create, update, or destroy |

### Terraform Workflow

```
   Write Code
       ↓
  terraform init          # download providers
       ↓
  terraform validate      # check syntax & consistency
       ↓
  terraform plan          # preview changes
       ↓
  terraform apply         # apply changes
       ↓
  Verify Resources        # check AWS console / CLI
       ↓
  terraform destroy       # tear down when done
```

### AWS S3 — Quick Facts

- **Object storage** for files, backups, logs, and static content
- **Globally unique names** required for bucket creation
- **Versioning** protects against accidental overwrites and deletions
- **Scalable storage** with virtually unlimited capacity
- **Pay only for what you use** — no upfront cost

### Terraform State

- Stored in `terraform.tfstate` (locally, by default)
- Tracks every resource Terraform manages
- Used to determine what to **create, update, or destroy**
- **Should never be edited manually** — use `terraform state` subcommands
- For teams, use **remote state** (S3 + DynamoDB, Terraform Cloud, etc.)

### Useful State Commands

```bash
terraform state list              # list all managed resources
terraform state show <resource>   # show details of one resource
terraform state mv                # rename a resource in state
terraform state rm                # remove a resource from state (does NOT destroy it)
terraform state pull              # download remote state locally
```

### The Destroy Command

```bash
terraform destroy
```

- Removes **all resources** tracked in the current Terraform state
- Uses the same configuration that created the resources
- **No separate `destroy.tf` file is required**
- Always review the destroy plan before confirming

## Challenge Extensions

Stretch goals once the basics work:

1. **Enable server-side encryption (AES256)**

   ```hcl
   resource "aws_s3_bucket_server_side_encryption_configuration" "demo" {
     bucket = aws_s3_bucket.demo.id

     rule {
       apply_server_side_encryption_by_default {
         sse_algorithm = "AES256"
       }
     }
   }
   ```

2. **Generate a random bucket name** using the Random provider

   ```hcl
   terraform {
     required_providers {
       random = {
         source  = "hashicorp/random"
         version = "~> 3.0"
       }
     }
   }

   resource "random_pet" "bucket_name" {
     length = 2
   }

   resource "aws_s3_bucket" "demo" {
     bucket = random_pet.bucket_name.id
   }
   ```

3. **Add tags to the bucket**

   ```hcl
   resource "aws_s3_bucket" "demo" {
     bucket = "your-unique-bucket-name"

     tags = {
       Environment = "dev"
       Owner       = "cloud-engineering"
       ManagedBy   = "Terraform"
       Project     = "terraform-day1"
     }
   }
   ```

4. **Configure `force_destroy = true`**

   Useful for non-production buckets — allows Terraform to delete the bucket even if it contains objects.

   ```hcl
   resource "aws_s3_bucket" "demo" {
     bucket          = "your-unique-bucket-name"
     force_destroy   = true
   }
   ```

   > 🚨 Never use this on production buckets. It will wipe all data without confirmation.

5. **Explore the Terraform state**

   ```bash
   terraform state list
   terraform state show aws_s3_bucket.demo
   ```
