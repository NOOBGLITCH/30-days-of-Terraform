# Terraform Day 1: Create Your First AWS S3 Bucket

The Cloud Engineering team has requested the creation of an Amazon S3 bucket using Terraform to begin **Infrastructure as Code (IaC)** adoption. Follow this hands-on guide to provision, verify, and clean up an S3 bucket using Terraform.

---

## Learning Objectives

By the end of this exercise, you will:

- Install Terraform on your local machine
- Configure AWS credentials
- Create an S3 bucket using Terraform
- Enable bucket versioning
- Apply the configuration and verify the bucket exists
- Destroy the infrastructure cleanly when finished

---

## Prerequisites

| Requirement | Notes |
|-------------|-------|
| AWS Account | Free tier is fine |
| IAM User | With `AmazonS3FullAccess` (or admin for learning) |
| AWS Access Key + Secret | Generated from IAM console |
| Terraform >= 1.5 | Installed locally |
| AWS CLI | For verification steps |

### Step 0a: Install Terraform

Pick your OS:

#### macOS (Homebrew)

```bash
brew tap hashicorp/tap
brew install hashicorp/tap/terraform
terraform -version
```

#### Linux — Debian / Ubuntu (apt)

```bash
sudo apt-get update && sudo apt-get install -y gnupg software-properties-common

wget -O- https://apt.releases.hashicorp.com/gpg | \
  sudo gpg --dearmor -o /usr/share/keyrings/hashicorp-archive-keyring.gpg

echo "deb [signed-by=/usr/share/keyrings/hashicorp-archive-keyring.gpg] \
  https://apt.releases.hashicorp.com $(lsb_release -cs) main" | \
  sudo tee /etc/apt/sources.list.d/hashicorp.list

sudo apt update
sudo apt install terraform
terraform -version
```

#### Windows (Chocolatey)

```powershell
choco install terraform
terraform -version
```

### Step 0b: Install the AWS CLI

#### Linux — Debian / Ubuntu / RHEL / CentOS

```bash
curl "https://awscli.amazonaws.com/awscli-exe-linux-x86_64.zip" -o "awscliv2.zip"
unzip awscliv2.zip
sudo ./aws/install
aws --version
```

#### Windows (MSI installer)

Download from: https://docs.aws.amazon.com/cli/latest/userguide/getting-started-install.html

Verify in PowerShell:
```powershell
aws --version
```

### Step 0c: Configure AWS Credentials

```bash
aws configure
# AWS Access Key ID:     AKIAxxxxxxxxxxxx
# AWS Secret Access Key: ****************************************
# Default region name:   ap-south-1
# Default output format: json
```

This creates two files:

- `~/.aws/credentials` — your access keys
- `~/.aws/config` — region + output format

> **Note:** Never commit AWS credentials. Use `~/.aws/credentials` or environment variables.

## Part 1: Provision the S3 Bucket

### 1. Create a Terraform project directory

```bash
mkdir terraform-day1
cd terraform-day1
```

### 2. Create a Terraform configuration file

```bash
touch main.tf
```

### 3. Add the configuration

```hcl
terraform {
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 6.0"
    }
    
    # CHANGE: Added random provider declaration
    random = {
      source  = "hashicorp/random"
      version = "~> 3.7"
    }
  }
}

provider "aws" {
  region = "ap-south-1"
}

# CHANGE: Added random_id resource to generate unique bucket suffix
# Generates 4 random bytes (8 hex characters) for globally unique bucket name
resource "random_id" "bucket_suffix" {
  byte_length = 4
}

# CHANGE: Modified bucket name to use random suffix instead of hardcoded name
# Original: bucket = "your-unique-bucket-name"
# New: Uses random_id suffix for guaranteed uniqueness
resource "aws_s3_bucket" "example" {
  bucket = "terraform-example-${random_id.bucket_suffix.hex}"
  
  # CHANGE: Added tags for better resource management
  tags = {
    Name        = "Terraform Day1 Bucket"
    Environment = "dev"
    ManagedBy   = "Terraform"
  }
}

resource "aws_s3_bucket_versioning" "example" {
  bucket = aws_s3_bucket.example.id

  versioning_configuration {
    status = "Enabled"
  }
}

resource "aws_s3_bucket_server_side_encryption_configuration" "example" {
  bucket = aws_s3_bucket.example.id

  rule {
    apply_server_side_encryption_by_default {
      sse_algorithm = "AES256"
    }
  }
}

# CHANGE: Added output for bucket name
output "bucket_name" {
  description = "The name of the created S3 bucket"
  value       = aws_s3_bucket.example.bucket
}

# CHANGE: Added output to show the random suffix for learning purposes
output "random_suffix" {
  description = "The random hex suffix generated for the bucket"
  value       = random_id.bucket_suffix.hex
}
```

### Summary of Changes Made to Original Configuration

| Section | Original | Change Made |
|---------|----------|-------------|
| `terraform` block | Missing random provider | Added random provider declaration |
| Provider section | Only AWS provider | Added random provider (implicitly required) |
| Bucket naming | Hardcoded static name | Uses `${random_id.bucket_suffix.hex}` for uniqueness |
| Random resource | Not present | Added `random_id` resource with `byte_length = 4` |
| Tags | Not present | Added three tags for identification |
| Outputs | None | Added `bucket_name` and `random_suffix` outputs |

### 4. Initialize Terraform

```bash
terraform init
```

Expected output:
```
Terraform has been successfully initialized!
```

### 5. Validate the configuration

```bash
terraform validate
```

### 6. Preview infrastructure changes

```bash
terraform plan
```

### 7. Create the S3 bucket

```bash
terraform apply
```

Type `yes` when prompted.

Expected output showing the random suffix:
```
random_id.bucket_suffix: Creating...
random_id.bucket_suffix: Creation complete after 0s [id=7c5a3b9e]

aws_s3_bucket.example: Creating...
aws_s3_bucket.example: Creation complete...

Outputs:

bucket_name = "terraform-example-7c5a3b9e"
random_suffix = "7c5a3b9e"
```

### 8. Verify bucket creation

```bash
aws s3 ls
```

Or query the API:

```bash
aws s3api list-buckets --query "Buckets[].Name"
```

Verify versioning is enabled:

```bash
aws s3api get-bucket-versioning --bucket terraform-example-7c5a3b9e
```

Verify encryption is enabled:

```bash
aws s3api get-bucket-encryption --bucket terraform-example-7c5a3b9e
```

## Part 2: Cleanup — Destroy Infrastructure

### 9. Preview resources to be destroyed

```bash
terraform plan -destroy
```

### 10. Destroy the S3 bucket

```bash
terraform destroy
```

Type `yes` when prompted.

### 11. Verify bucket deletion

```bash
aws s3 ls
```

The bucket should no longer appear in the list.

### 12. Remove local Terraform files (Optional)

```bash
rm -rf .terraform
rm -f terraform.tfstate
rm -f terraform.tfstate.backup
rm -f .terraform.lock.hcl
```

## Part 3: Targeted Operations

### Destroy a single resource

```bash
terraform destroy -target=aws_s3_bucket.example
```

### Apply a single resource

```bash
terraform apply -target=aws_s3_bucket_versioning.example
```

> **Note:** Use `-target` sparingly, primarily for troubleshooting or emergency changes.

## Good to Know

### What is Terraform?

| Concept | Description |
|---------|-------------|
| **Infrastructure as Code (IaC)** | Define infrastructure using code instead of manual clicks |
| **Declarative Language** | You describe the desired state; Terraform figures out how to achieve it |
| **Provider-Based Architecture** | Works with AWS, Azure, GCP, Kubernetes, and 3,000+ others |
| **State Management** | Tracks managed resources to know what to create, update, or destroy |

### Terraform Workflow

```
   Write Code
       ↓
  terraform init          # download providers
       ↓
  terraform validate      # check syntax & consistency
       ↓
  terraform plan          # preview changes
       ↓
  terraform apply         # apply changes
       ↓
  Verify Resources        # check AWS console / CLI
       ↓
  terraform destroy       # tear down when done
```

### About the random_id Resource

The `random_id` resource generates random data that persists in Terraform state:

| Attribute | Description | Example Output |
|-----------|-------------|----------------|
| `byte_length = 4` | Generates 4 random bytes | `[0x7c, 0x5a, 0x3b, 0x9e]` |
| `.hex` | Hex encoding (8 characters) | `7c5a3b9e` |
| `.dec` | Decimal encoding | `2084985758` |
| `.b64_url` | Base64 URL-safe encoding | `fFo7ng` |

**Why use random_id for S3 buckets:**
- S3 bucket names must be globally unique across all AWS accounts
- Prevents naming conflicts when multiple people run the same code
- No need to manually invent unique names
- Each `terraform apply` creates a completely new unique bucket
