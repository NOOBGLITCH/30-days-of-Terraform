# Day 2: Terraform Providers & Versioning

## What is a Terraform Provider?

A **Terraform Provider** is a plugin that enables Terraform to communicate with cloud platforms, SaaS services, and APIs.

Popular providers: AWS, Azure, GCP, Kubernetes, Docker, GitHub, Random, Local

---

## Terraform Core vs Provider

| Terraform Core | Provider |
|----------------|----------|
| Main application | Plugin for specific platform |
| Reads `.tf` files | Talks to cloud APIs |
| Creates execution plan | Executes API calls |
| Manages state | Creates/updates/deletes resources |

**Think:** Core = Brain, Provider = Translator

---

## Provider Source

Terraform downloads providers from the Terraform Registry.

```hcl
terraform {
  required_providers {
    aws = {
      source = "hashicorp/aws"  # namespace/provider_name
    }
  }
}
```

---

## Why Provider Versions Matter

- Compatibility with Terraform version
- Stable deployments
- Access to new features
- Bug fixes and security updates
- Prevent breaking changes

**Version Example:**
- Terraform Core: `1.13.2`
- AWS Provider: `5.95.0`
- Random Provider: `3.7.2`

---

## Required Providers Block

```hcl
terraform {
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.0"
    }
  }
}
```

## Version Constraints

### Common Operators

| Operator | Meaning | Example |
|----------|---------|---------|
| `=` | Exact version | `= 5.95.0` |
| `!=` | Exclude version | `!= 5.94.0` |
| `>` | Greater than | `> 5.0` |
| `>=` | Greater than or equal | `>= 5.0` |
| `<` | Less than | `< 6.0` |
| `<=` | Less than or equal | `<= 5.95` |
| `~>` | Pessimistic constraint | `~> 5.0` |

### Examples

```hcl
# Exact version
version = "= 5.95.0"

# Range
version = ">= 5.0, < 6.0"

# Pessimistic (~>)
version = "~> 5.0"    # Allows: 5.0-5.99, Blocks: 6.0
version = "~> 5.95"   # Allows: 5.95-5.95.x, Blocks: 5.96, 6.0
```

## Real-World Example

```hcl
terraform {
  required_version = ">= 1.6.0"
  
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.95"
    }
  }
}

provider "aws" {
  region = "ap-south-1"
}
```

---

## Best Practices

1. **Always specify provider versions**
2. **Prefer `~>` for stable upgrades**
3. **Avoid latest version without testing**
4. **Keep Terraform Core and providers compatible**
5. **Test upgrades in dev before production**
6. **Commit `.terraform.lock.hcl`** to version control
