# Day 03: Terraform Configuration Basics

Today I learned the three fundamental building blocks of every Terraform configuration: the `terraform` block, the `provider` block, and the `resource` block. Together, these define **what** infrastructure to manage, **where** to manage it, and **how** to connect to the cloud platform.

---

## The Three Core Blocks

Every Terraform project starts with these three blocks:

| Block | Purpose |
|-------|---------|
| `terraform` | Declares required providers and version constraints |
| `provider` | Configures the cloud platform connection (e.g., AWS region) |
| `resource` | Defines the actual infrastructure component to create |

---

## 1. The `terraform` Block

The `terraform` block tells Terraform which providers to download and which versions to use.

```hcl
terraform {
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 6.0"
    }
  }
}
```

- **`source`** — Where to download the provider from the Terraform Registry (`namespace/provider_name`)
- **`version`** — A version constraint using operators like `~>` (pessimistic), `>=`, `<`, etc.

> The `~>` operator means "accept any patch version within the same minor version." For example, `~> 6.0` allows `6.0.0` through `6.99.99`, but not `7.0.0`.

---

## 2. The `provider` Block

The `provider` block configures how Terraform connects to the cloud platform.

```hcl
provider "aws" {
  region = "us-east-1"
}
```

This tells Terraform to interact with AWS in the `us-east-1` region. All subsequent AWS resources will be created in this region unless overridden.

---

## 3. The `resource` Block

The `resource` block defines the actual infrastructure component to create.

```hcl
resource "aws_s3_bucket" "tf_test_baivab_bucket" {
  bucket = "my-tf-test-baiv-bucket-101"

  tags = {
    Name        = "My bucket"
    Environment = "Dev"
  }
}
```

- **`aws_s3_bucket`** — The resource type (provided by the AWS provider)
- **`tf_test_baivab_bucket`** — The resource name (a local label for referencing)
- **`bucket`** — The globally unique name for the S3 bucket
- **`tags`** — Key-value pairs for organizing and identifying resources

---

## Full Configuration

Here is the complete `main.tf` from today's exercise:

```hcl
terraform {
  required_providers {
    aws = {
      source = "hashicorp/aws"
      version = "~> 6.0"
    }
  }
}

provider "aws" {
  region = "us-east-1"
}

resource "aws_s3_bucket" "tf_test_baivab_bucket" {
  bucket = "my-tf-test-baiv-bucket-101"

  tags = {
    Name        = "My bucket"
    Environment = "Dev"
  }
}
```

## Commands Used

```bash
terraform init      # Download the AWS provider
terraform validate  # Check syntax and consistency
terraform plan      # Preview what will be created
terraform apply     # Create the S3 bucket
terraform destroy   # Remove the S3 bucket
```

---

## What I Learned

* The `terraform` block declares which providers Terraform needs and their version constraints.
* The `provider` block configures the connection to the cloud platform (region, credentials, etc.).
* The `resource` block defines the actual infrastructure object to create.
* Every Terraform configuration follows this three-block pattern, regardless of complexity.
* S3 bucket names must be globally unique across all AWS accounts.
* Tags help organize and identify resources in the AWS console.

---

## Good to Know 💡

* Terraform automatically downloads providers from the [Terraform Registry](https://registry.terraform.io/) during `terraform init`.
* The `required_providers` block pins provider versions to prevent unexpected breaking changes.
* Resource names are local identifiers — they don't appear in AWS, only in Terraform state and references.
* Always run `terraform validate` before `terraform apply` to catch syntax errors early.
* The `tags` argument is supported by most AWS resources and is a best practice for cost allocation and resource management.
