## Terraform Variables and Dynamic S3 Bucket Creation

Today, I explored one of the most important Terraform concepts: **Variables**. Instead of hardcoding values directly into the configuration, variables allow us to create flexible and reusable infrastructure. I also learned how to use the **Random provider** to generate unique values and avoid naming conflicts when creating AWS resources.

### What I Built

In this task, I:

* Configured the AWS and Random providers
* Created variables for the AWS region and bucket name prefix
* Generated a random hexadecimal suffix
* Created an AWS S3 bucket with a unique name
* Displayed the bucket name using Terraform outputs

### Why Variables Matter

Hardcoding values works for small projects, but it becomes difficult to manage as infrastructure grows. Variables make configurations reusable and easier to maintain.

Example:

```hcl
variable "aws_region" {
  default = "ap-south-1"
}

variable "bucket_prefix" {
  default = "my-custom-bucket"
}
```

With variables, I can deploy the same code to different environments without modifying the actual Terraform files.

### Creating a Unique S3 Bucket Name

One interesting thing I learned is that **S3 bucket names must be globally unique across all AWS accounts**. To solve this, I used the Random provider.

```hcl
resource "random_id" "suffix" {
  byte_length = 4
}
```

Then I combined the bucket prefix with the random value:

```hcl
resource "aws_s3_bucket" "bucket" {
  bucket = "${var.bucket_prefix}-${random_id.suffix.hex}"
}
```

This automatically creates unique bucket names such as:

```text
my-custom-bucket-4a8b2c1d
```

### Output Values

Terraform outputs are useful for displaying important information after deployment.

```hcl
output "bucket_name" {
  value = aws_s3_bucket.bucket.id
}
```

- **Full code (main.tf)**
```hcl
# Configure required cloud and utility providers
terraform {
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 6.0"
    }
    random = {
      source  = "hashicorp/random"
      version = "~> 3.7"
    }
  }
}

# Set up the AWS provider with the target region
provider "aws" {
  region = var.aws_region
}

# Define the deployment region variable
variable "aws_region" {
  type    = string
  default = "ap-south-1"
}

# --- NEW VARIABLE ADDED HERE ---
# Define the bucket name prefix variable
variable "bucket_prefix" {
  type    = string
  default = "my-custom-bucket"
}

# Generate a safe, unique hexadecimal suffix (e.g., 4a8b2c1d)
resource "random_id" "suffix" {
  byte_length = 4
}

# Create the S3 bucket combining the variable and the random suffix
resource "aws_s3_bucket" "bucket" {
  bucket = "${var.bucket_prefix}-${random_id.suffix.hex}"
}

# Print the final unique bucket name to the terminal screen
output "bucket_name" {
  value = aws_s3_bucket.bucket.id
}
```

After running Terraform, the bucket name is displayed directly in the terminal, making it easy to verify the deployment.

* Always use variables instead of hardcoding values whenever possible.
* S3 bucket names can contain lowercase letters, numbers, and hyphens only.
* Outputs are useful when integrating Terraform modules.
* Random resources help avoid deployment failures caused by duplicate names.
* Following Infrastructure as Code (IaC) best practices makes configurations easier to scale and maintain.
