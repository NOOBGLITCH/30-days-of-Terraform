# Day 5 of 30 Days of Terraform 🚀

## Organizing Terraform Code with Separate Files

Today, I learned how to structure a Terraform project properly by separating configurations into different files. While Terraform can run everything from a single `main.tf` file, organizing code into dedicated files makes projects cleaner, easier to maintain, and more scalable.

## Project Goal

I refactored my S3 bucket project by separating:

* Providers
* Variables
* Locals
* Resources
* Outputs
* `.gitignore`

into individual files following Terraform best practices.

## Project Structure

```text
terraform-s3-bucket/
├── provider.tf
├── variables.tf
├── locals.tf
├── main.tf
├── outputs.tf
├── terraform.tfvars
└── .gitignore
```

## provider.tf

Used to configure providers required by Terraform.

```hcl
terraform {
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 6.0"
    }

    random = {
      source  = "hashicorp/random"
      version = "~> 3.7"
    }
  }
}

provider "aws" {
  region = var.aws_region
}
```

### Learned

* Providers connect Terraform to external services.
* Version pinning ensures consistent deployments.

---

## variables.tf

Used for reusable values.

```hcl
variable "aws_region" {
  type    = string
  default = "ap-south-1"
}

variable "bucket_prefix" {
  type    = string
  default = "my-custom-bucket"
}
```

### Learned

* Variables reduce hardcoding.
* Makes code reusable across environments.

---

## locals.tf

Used for calculated or reusable values inside the project.

```hcl
locals {
  bucket_name = "${var.bucket_prefix}-${random_id.suffix.hex}"
}
```

### Learned

* Locals help avoid repeating the same expressions.
* Improves readability and maintainability.

---

## main.tf

Contains the actual infrastructure resources.

```hcl
resource "random_id" "suffix" {
  byte_length = 4
}

resource "aws_s3_bucket" "bucket" {
  bucket = local.bucket_name
}
```

### Learned

* Resources define infrastructure components.
* Local values can be referenced using `local.<name>`.

---

## outputs.tf

Displays useful information after deployment.

```hcl
output "bucket_name" {
  value = aws_s3_bucket.bucket.id
}
```

### Learned

* Outputs provide important deployment details.
* Useful when working with modules.

---

## terraform.tfvars

Stores custom variable values.

```hcl
aws_region   = "ap-south-1"
bucket_prefix = "terraform-demo"
```

### Learned

* Keeps configuration separate from code.
* Easy environment customization.

---

## .gitignore

Important files that should not be pushed to GitHub.

```gitignore
.terraform/
*.tfstate
*.tfstate.*
crash.log
terraform.tfvars
.terraform.lock.hcl
```

### Learned

* Prevents accidental exposure of sensitive information.
* Keeps repositories clean.
* Avoids committing state files.

## Good to Know 💡

* Terraform automatically loads all `.tf` files in a directory.
* File names don't matter; Terraform merges them during execution.
* Keeping code modular makes future scaling easier.
* Most real-world Terraform projects follow this structure.
* A clean project structure improves collaboration in teams.
