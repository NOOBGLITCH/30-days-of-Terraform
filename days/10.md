# Terraform Dynamic Blocks, Conditional Expressions & Splat Expressions — Day 10 of 30 Days of Terraform

**Day 10** is about writing *less code that does more*. Three language features let you build flexible, DRY Terraform: **conditional expressions** (decisions), **dynamic blocks** (repeatable nested blocks), and **splat expressions** (bulk attribute extraction). These are the tools that turn brittle copy-paste configs into reusable modules.

## 1. Conditional Expressions

The ternary operator picks a value based on a condition:

```hcl
condition ? true_value : false_value
```

Example — a `Tier` tag that differs by environment:

```hcl
resource "aws_s3_bucket" "app" {
  bucket = "${var.app_name}-${var.environment}"

  tags = {
    Environment = var.environment
    Tier = var.environment == "prod" ? "Production-Ready" : "Non-Prod"
  }
}
```

Rules:

- The condition must evaluate to a `bool`.
- Both branches must be the **same type** (or Terraform must be able to unify them).
- You can nest conditionals, but prefer `lookup()`/`try()` for readability when there are many branches.

Conditionals also work great in outputs and locals:

```hcl
output "tier_label" {
  value = var.environment == "prod" ? "Production-Ready" : "Non-Prod"
}
```

## 2. Dynamic Blocks

Some arguments are **repeated nested blocks** (e.g., `ingress` in a security group). Instead of hand-writing each one, a `dynamic` block loops over a collection and generates them.

```hcl
resource "aws_security_group" "web" {
  name = "${var.app_name}-sg"

  dynamic "ingress" {
    for_each = var.ingress_rules
    content {
      from_port   = ingress.value.port
      to_port     = ingress.value.port
      protocol    = ingress.value.protocol
      cidr_blocks = [ingress.value.cidr]
    }
  }
  # ...
}
```

How it works:

- `for_each` is any collection (list/set/map).
- Inside `content`, `ingress.value` is the current item (`ingress.key` for maps).
- The block label (`"ingress"`) must match the nested block type the resource expects.

### Conditional dynamic block

Set `for_each` to an empty collection to generate **zero** blocks. Combine with a conditional to toggle a block on/off:

```hcl
dynamic "ingress" {
  for_each = var.enable_https ? [443] : []
  content {
    from_port   = ingress.value
    to_port     = ingress.value
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }
}
```

When `enable_https = false`, `for_each = []` → no HTTPS rule is created.

Best practices:

- Prefer `dynamic` when the number of blocks is variable/data-driven.
- If the blocks are **fixed and few**, writing them literally is clearer — don't force `dynamic` everywhere.
- Watch for `dynamic` blocks nested inside `dynamic` blocks; they get hard to read fast.

## 3. Splat Expressions

When a resource uses `count` (or `for_each`), it becomes a **collection**. The splat expression `[*]` extracts one attribute from every element into a list — in a single line.

```hcl
resource "aws_instance" "web" {
  count         = var.instance_count
  ami           = "ami-006f82a1d5a27da54"
  instance_type = "t3.micro"
}
```

```hcl
output "instance_ids" {
  value = aws_instance.web[*].id
}
```

`aws_instance.web[*].id` is shorthand for:

```hcl
[for inst in aws_instance.web : inst.id]
```

Variants:

- `resource[*].attr` — splat over a list produced by `count`.
- `resource[*].block[*].attr` — chained splat for nested repeated blocks.
- `resource.attr` (no `[*]`) — only valid when the resource is a single instance (no `count`/`for_each`).

Caution: if the resource has **no** `count`, use `aws_instance.web.id` (no splat) — adding `[*]` there is a type error.

## Connecting the Dots

```
variables.tf
  ├─ enable_https (bool) ──► conditional dynamic block (ingress 443 on/off)
  ├─ ingress_rules (list) ─► dynamic block (repeat ingress rules)
  └─ instance_count (number) ─► count on aws_instance.web
                                      │
                                      └─► [*] splat in outputs
```

All three features compose: a conditional decides *whether* a dynamic block appears, `count` decides *how many* instances exist, and a splat collects their attributes.

---

## Best Practices Recap

1. Use **conditional expressions** for small, type-safe choices.
2. Use **dynamic blocks** for variable, data-driven repeated blocks — not fixed ones.
3. Use **splat `[*]`** to pull attributes out of `count`/`for_each` resources cleanly.
4. Keep `dynamic` blocks readable; fall back to literal blocks when static.
5. Match splat usage to whether the resource is a list (has `count`/`for_each`).
