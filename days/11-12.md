# Day 11-12: Terraform Functions & Multi-File Project Structure

Today I explored Terraform built-in functions and learned how to organize a real-world Terraform project across multiple files. The `Terraform files/day11-12` folder contains 12 assignments demonstrating essential functions — from string manipulation and data lookups to cost calculations and file handling — all organized into separate `provider.tf`, `variables.tf`, `main.tf`, and `outputs.tf` files.

---

## Project Structure

A well-organized Terraform project separates concerns into dedicated files:

```text
Terraform files/day11-12/
├── provider.tf      # Provider configuration and version constraints
├── variables.tf     # Input variables with types, defaults, and validations
├── main.tf          # Resources, locals, and data sources
├── outputs.tf       # Output values for deployment results
└── terraform.tfvars # (optional) Variable value overrides
```

---

## Provider Configuration (`provider.tf`)

The provider file declares which cloud platform Terraform interacts with and pins version constraints.

```hcl
terraform {
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.0"
    }
  }
  required_version = ">= 1.0"
}

provider "aws" {
  region = "us-east-1"
}
```

- **`required_version`** — Ensures the Terraform Core version is compatible
- **`required_providers`** — Pins the AWS provider to `~> 5.0` for stability

## Main Configuration (`main.tf`)

The main file contains all 12 assignments demonstrating Terraform built-in functions. Each assignment is commented out so you can uncomment and test them individually.

### Assignment 1: Project Naming Convention — `lower()`, `replace()`

```hcl
locals {
  formatted_project_name = lower(replace(var.project_name, " ", "-"))
}

resource "aws_resourcegroups_group" "project" {
  name = local.formatted_project_name

  resource_query {
    query = jsonencode({
      ResourceTypeFilters = ["AWS::AllSupported"]
      TagFilters = [{
        Key    = "Project"
        Values = [local.formatted_project_name]
      }]
    })
  }

  tags = {
    Name    = local.formatted_project_name
    Project = local.formatted_project_name
  }
}
```

> `lower()` converts strings to lowercase. `replace()` swaps characters — here, spaces become hyphens.

### Assignment 2: Resource Tagging — `merge()`

```hcl
locals {
  merged_tags = merge(var.default_tags, var.environment_tags)
}

resource "aws_vpc" "tagged_vpc" {
  cidr_block = "10.0.0.0/16"

  tags = local.merged_tags
}
```

> `merge()` combines two or more maps. Later maps override keys from earlier ones.

### Assignment 3: S3 Bucket Naming — `substr()`, `replace()`, `lower()`

```hcl
locals {
  formatted_bucket_name = replace(
    replace(
      lower(substr(var.bucket_name, 0, 63)),
      " ", ""
    ),
    "!", ""
  )
}

resource "aws_s3_bucket" "storage" {
  bucket = local.formatted_bucket_name

  tags = {
    Name        = local.formatted_bucket_name
    Environment = var.environment
  }
}
```

> S3 bucket names must be ≤63 characters, lowercase, with no spaces or special characters. `substr()` truncates, `lower()` normalizes case, and `replace()` strips invalid characters.

### Assignment 4: Security Group Port Configuration — `split()`, `join()`, `for` expression

```hcl
locals {
  port_list = split(",", var.allowed_ports)

  sg_rules = [for port in local.port_list : {
    name        = "port-${port}"
    port        = port
    description = "Allow traffic on port ${port}"
  }]

  formatted_ports = join("-", [for port in local.port_list : "port-${port}"])
}

resource "aws_vpc" "sg_vpc" {
  cidr_block = "10.1.0.0/16"

  tags = {
    Name       = "security-group-demo-vpc"
    Assignment = "4"
  }
}

resource "aws_security_group" "app_sg" {
  name        = "app-security-group"
  description = "Security group with dynamic ports"
  vpc_id      = aws_vpc.sg_vpc.id

  dynamic "ingress" {
    for_each = { for rule in local.sg_rules : rule.name => rule }
    content {
      description = ingress.value.description
      from_port   = tonumber(ingress.value.port)
      to_port     = tonumber(ingress.value.port)
      protocol    = "tcp"
      cidr_blocks = ["0.0.0.0/0"]
    }
  }

  egress {
    from_port   = 0
    to_port     = 0
    protocol    = "-1"
    cidr_blocks = ["0.0.0.0/0"]
  }

  tags = {
    Name = "app-security-group"
  }
}
```

> `split()` breaks a string into a list. `join()` concatenates a list into a string. The `for` expression creates dynamic collections. `dynamic` blocks generate repeated configuration blocks at runtime.

### Assignment 5: Environment Configuration Lookup — `lookup()`

```hcl
locals {
  instance_size = lookup(var.instance_sizes, var.environment, "t2.micro")
}

data "aws_ami" "amazon_linux" {
  most_recent = true
  owners      = ["amazon"]

  filter {
    name   = "name"
    values = ["amzn2-ami-hvm-*-x86_64-gp2"]
  }
}

resource "aws_instance" "app_server" {
  ami           = data.aws_ami.amazon_linux.id
  instance_type = local.instance_size

  tags = {
    Name        = "app-server-${var.environment}"
    Environment = var.environment
    Size        = local.instance_size
  }
}
```

> `lookup()` retrieves a value from a map with a fallback default if the key is missing.

### Assignment 6: Instance Type Validation — `length()`, `contains()`, `can()`, `regex()`

Validation is defined in `variables.tf` using `validation` blocks:

```hcl
variable "instance_type" {
  type        = string
  description = "EC2 instance type"
  default     = "t2.micro"

  validation {
    condition     = length(var.instance_type) >= 2 && length(var.instance_type) <= 20
    error_message = "Instance type must be between 2 and 20 characters"
  }

  validation {
    condition     = can(regex("^t[2-3]\\.", var.instance_type))
    error_message = "Instance type must start with t2 or t3"
  }
}
```

> `length()` counts elements in a string or collection. `contains()` checks if a list includes a value. `can()` catches errors from expressions (returns `true` if the expression succeeds). `regex()` matches strings against regular expressions.

### Assignment 8: File Path Processing — `fileexists()`, `dirname()`, `file()`

```hcl
locals {
  config_files = [
    "./configs/main.tf",
    "./configs/variables.tf"
  ]

  file_status = { for file_path in local.config_files :
    file_path => fileexists(file_path)
  }

  config_dirs = { for file_path in local.config_files :
    file_path => dirname(file_path)
  }
}
```

> `fileexists()` checks if a file exists at a given path. `dirname()` extracts the directory portion of a path. `file()` reads file contents (used in Assignment 12).

### Assignment 9: Resource Location Management — `toset()`, `concat()`

```hcl
locals {
  all_locations    = concat(var.user_locations, var.default_locations)
  unique_locations = toset(local.all_locations)
}
```

> `concat()` combines lists (including duplicates). `toset()` converts a list to a set, automatically removing duplicates.

### Assignment 10: Cost Calculation — `abs()`, `max()`, `sum()`

```hcl
locals {
  positive_costs = [for cost in var.monthly_costs : abs(cost)]

  max_cost = max(local.positive_costs...)

  total_cost = sum(local.positive_costs)

  avg_cost = local.total_cost / length(local.positive_costs)
}
```

> `abs()` returns the absolute value. `max()` finds the largest value in a list. `sum()` adds all values. The spread operator (`...`) passes a list as individual arguments.

### Assignment 11: Timestamp Management — `timestamp()`, `formatdate()`

```hcl
locals {
  current_timestamp    = timestamp()
  resource_date_suffix = formatdate("YYYYMMDD", local.current_timestamp)
  tag_date_format      = formatdate("DD-MM-YYYY", local.current_timestamp)
  timestamped_name     = "backup-${local.resource_date_suffix}"
}

resource "aws_s3_bucket" "timestamped_bucket" {
  bucket = "my-backup-${local.resource_date_suffix}"

  tags = {
    Name       = local.timestamped_name
    CreatedOn  = local.tag_date_format
    Timestamp  = local.current_timestamp
  }
}
```

> `timestamp()` returns the current UTC timestamp in ISO 8601 format. `formatdate()` formats timestamps using pattern strings like `YYYYMMDD` or `DD-MM-YYYY`.

### Assignment 12: File Content Handling — `file()`, `jsondecode()`, `sensitive`

```hcl
locals {
  config_file_exists = fileexists("./config.json")

  config_data = local.config_file_exists ? jsondecode(file("./config.json")) : {
    database = {
      host     = "localhost"
      port     = 5432
      username = "default"
    }
  }
}

resource "aws_secretsmanager_secret" "app_config" {
  name        = "app-configuration-${formatdate("YYYYMMDD-hhmm", timestamp())}"
  description = "Application configuration from file"

  tags = {
    Name       = "app-config"
    Sensitive  = "true"
    ConfigFile = "./config.json"
  }
}

resource "aws_secretsmanager_secret_version" "app_config" {
  secret_id     = aws_secretsmanager_secret.app_config.id
  secret_string = jsonencode(local.config_data)
}
```

> `file()` reads a file's contents as a string. `jsondecode()` parses a JSON string into a Terraform value. `jsonencode()` does the reverse — converts Terraform values to JSON strings.

## Commands Used

```bash
terraform init      # Download providers and initialize the project
terraform validate  # Check syntax and consistency across all files
terraform plan      # Preview infrastructure changes
terraform apply     # Deploy the infrastructure
terraform output    # Display output values
terraform destroy   # Remove all managed resources
```

## What I Learned

* **String functions** — `lower()`, `upper()`, `replace()`, `substr()`, `split()`, `join()` manipulate text for naming and formatting.
* **Collection functions** — `merge()`, `concat()`, `toset()`, `length()`, `contains()` manage maps and lists.
* **Lookup functions** — `lookup()` retrieves map values with a fallback default.
* **Validation functions** — `can()`, `regex()`, `endswith()` validate inputs before deployment.
* **File functions** — `fileexists()`, `dirname()`, `file()` interact with the local filesystem.
* **Math functions** — `abs()`, `max()`, `min()`, `sum()` perform calculations on numeric values.
* **Timestamp functions** — `timestamp()` and `formatdate()` generate and format time values.
* **JSON functions** — `jsondecode()` and `jsonencode()` parse and serialize JSON data.
* **Sensitive data** — The `sensitive` attribute on variables and outputs hides values from CLI output.
* **Multi-file organization** — Separating `provider.tf`, `variables.tf`, `main.tf`, and `outputs.tf` keeps projects clean and maintainable.
* **Dynamic blocks** — The `dynamic` block generates repeated configuration entries from collections at runtime.

---

## Good to Know 💡

* All `.tf` files in a directory are automatically loaded and merged by Terraform — file names don't matter.
* Comment out assignments one at a time to test individual functions without conflicts.
* `validation` blocks in `variables.tf` run during `terraform validate` and `terraform plan`, catching errors before apply.
* `sensitive` variables and outputs hide their values from CLI output and logs — useful for credentials.
* Data sources (`data` blocks) read information from providers without creating resources.
* The spread operator (`...`) passes a list as individual arguments to functions like `max()` and `min()`.
* `formatdate()` uses Go-style time format patterns: `YYYY` (year), `MM` (month), `DD` (day), `hh` (hour), `mm` (minute).
* Always run `terraform fmt` to keep multi-file projects consistently formatted.
